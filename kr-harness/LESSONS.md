## 클라우드 전환 (2026-10-07)

- **L15 — codex·orca·opencode 의존 제거, 하니스를 `.claude/`로**. 사용자 지시 「코덱스 의존성 제거하고, 대부분 스킬 형식으로 변환」. 이유는 클라우드 세션과 routines에서는 로컬 CLI가 없기 때문이다. 단계는 스킬(kr-pipeline·kr-localize·kr-style·kr-verify·kr-polish·kr-refine)로, 격리 작업은 에이전트(kr-localizer·kr-polisher·kr-entry-refiner)로 바꿨다. 결정론 부분은 Node 스크립트로 남겼다. 스크립트는 `KR-GUIDE.md`를 찾아 저장소 루트를 정하므로 어디서 실행해도 된다.
- **L16 — 팬아웃은 Agent 도구로**. `entry-pass.mjs`의 워커 분산은 오케스트레이터가 kr-entry-refiner를 한 번에 최대 8개씩 병렬로 띄우는 방식으로 바뀌었다. 분할·구조검사·조립은 LLM 없이 `entries.mjs`가 한다. 그래서 「항목 하나 = 서브에이전트 하나」(L13)가 로컬과 클라우드에서 똑같이 지켜진다.
- **L17 — 숫자 다중집합 경고는 원문·입력과 직접 대조한다** (2026-10-10 정정). R11-02 e-41의 기름 예시를 “입력에 없는 사실 추가”라고 기록한 것은 잘못이었다. 중국 원문에는 아마씨유·들깨유에 해당하는 예시가 있고, 역사 입력 e-41-in.md에도 이미 있었다. 출력이 두 번째 문장에 “식물성 오메가-3는”을 다시 적으면서 숫자 3이 한 번 늘어난 것이 경고 원인이다. 공개 본문은 “아마씨유·들기름의 주성분입니다”로 최소 수정해 의미를 보존했다. 역사 실행의 입력·출력·strict 경고는 그대로 남겼다. 직접 대조 근거는 [제2절 조사 기록](chapters/02/2-research.md)의 마지막 절에 있다.
- **L18 — VM은 회수될 수 있다**. 클라우드 VM은 쉬다가 회수되고, 커밋하지 않은 파일은 사라진다. 그래서 단계마다 커밋하고, S7은 묶음마다 `entries/`를 커밋한다. `entries.mjs split`은 통과한 출력을 지우지 않아서 중간부터 다시 시작할 수 있다.
- **L19 — 클라우드 기본 네트워크(Trusted)에서는 조사가 막힌다**. law.go.kr, KOSIS, doi.org는 기본 허용 목록에 없다. 세션 시작 훅이 접속 여부를 점검해서 S1-S3를 할지 말지 알려 준다. 조사용 환경 `kr-research`(Full 또는 Custom)는 CLOUD.md에 있다.
- **L20 — 절 병렬은 세션 병렬로**. `pipeline.mjs launch`가 절마다 claude.ai/code 미리 채우기 링크를 만든다. 세션 하나가 절 하나, 브랜치 하나다. 그래서 워크트리를 손으로 관리할 필요가 없다.

- **L21 — API 키 의존 제거**. 사용자 지시 「API KEY에 의존하는 의존성은 좀 없애고 싶은데」. 그래서 claude-code-action 워크플로 두 개(@claude, 수동 파이프라인)를 지웠다. 둘 다 장기 토큰(`CLAUDE_CODE_OAUTH_TOKEN`)을 저장소 비밀값으로 넣어야 했다. 그 기능은 이렇게 대신한다. 수동 실행은 `pipeline.mjs launch` 링크와 routine의 Run now로, 예약은 routine 일정으로, PR 점검은 routine의 GitHub 트리거(GitHub App만 필요)로 한다. Actions에는 LLM 없는 kr-check만 남았다. routine 프롬프트 본문은 `kr-harness/routines/`에 커밋해서 저장소가 단일 원천이 되게 했다. 세션 시작 훅은 `ANTHROPIC_API_KEY` 같은 키가 셸에 있으면 경고한다(구독 로그인보다 우선하기 때문).

- **L22 — 병렬 안전 (2026-10-10)**. 세 가지가 세션 병렬을 막고 있었다. 이렇게 고쳤다.
  1. `new-run`의 ID가 「전역 최댓값 + 1」이라 동시에 돈 세션이 모두 R15를 받았다. 지금은 `R` + 절 번호 + 절 안 순번(`R18a`)이다. 다른 절끼리는 조정 없이 안 겹친다. 같은 트리에서 같은 절 8개를 동시에 5번 돌려도 40개가 모두 달랐다. 옛 R01~R14는 그대로 읽는다. ID에 '-'를 넣지 않는다(`R13-2`면 「R13-로 시작하는 폴더」가 둘이 된다).
  2. `report.html`과 인자 없는 `verify.mjs`가 남의 실행 파일(날짜 줄)까지 고쳐 PR끼리 충돌했다. 보고서는 main에서만 만들고, verify는 결과가 같으면 쓰지 않는다. `polish-queue.md` 표 끝에 줄을 덧붙이는 일도 그만뒀다.
  3. 세션 시작 훅이 5초 한 번 실패로 「접속 불가」를 띄웠다. 실제로는 끊김이었다. law.go.kr은 8번 중 5번 열렸고, nhis·moel은 WebFetch로 열렸다. 지금은 도메인마다 3번 시도하고 끊김·차단을 나눠 알린다. Europe PMC는 REST API로 본다.

- **L23 — 한 세션 오케스트레이션 (2026-10-10, 2026-10-next-publish 첫 세션)**. 세션 하나가 서브에이전트로 34절을 돌릴 때 배운 것. 자세한 운영 요령은 [goals/handoff.md](goals/handoff.md) 6절.
  1. 첫 Claude 세션의 한도는 20개였지만 환경마다 다르다. 현재 Codex는 오케스트레이터 포함 7개다. 슬롯을 모두 조사(S1-S3)에 쓰면 짧은 S7 항목 작업이 줄을 서므로 S6·S7·검토 자리를 남긴다. 모델도 루트 AGENTS.md에 따라 Opus ↔ gpt-6.1-sol로 대응한다.
  2. 대화가 중단되면 백그라운드 에이전트가 모두 끝난다. 산출물은 중간 상태로 남는다. S6은 `meta.json`의 `polished`, S7은 `entries.mjs pending`, S1-S3은 항목 수와 `## TODO` 절로 끝났는지 판단한다.
  3. 공개된 절을 고치면 리뷰 해시가 깨진다. 독자를 잘못 이끌 warn은 조립 전에 「수정 → 재검토」로 고친다(3회차까지). 공개 뒤 손볼 것은 모아서 절마다 한 번에 재검토한다.
  4. 적합성 검토가 잡은 것은 대부분 「한국 제도가 원문과 다른데 원문 구조를 그대로 옮긴 곳」이었다. 예: 산재 자해 인정 사유 누락, 피부양자 범위, 응급피임약이 전문의약품, ORS 허가 의약품 없음. 조사 단계 지시에 「원문과 반대가 되는 한국 제도」를 적극 찾으라고 넣으면 검토 회차가 준다.

## 전체 제작 과정에서 확인한 교훈 (2026-10-10)

- **L24 — S7은 새 격리 에이전트와 strict 검사로 끝낸다**. 항목마다 독립 컨텍스트로 개선하고 숫자·URL·DOI·비용태그·필드 구조를 검사한다. 제19절 제18항 첫 출력에서 국세상담 번호 126이 빠져 새 에이전트로 재시도했다. 문장이 자연스러워도 이런 누락은 통과시키지 않는다. 중단 후에는 `entries.mjs pending`으로 실제 미완료 항목을 확인한다.
- **L25 — S4가 존댓말과 직접 인용을 보호해도 S6은 필요하다**. 기존 존댓말·직접 인용·URL·DOI 보호와 반복 실행 등 CLI 회귀 9건을 확인했다([진행 기록](goals/2026-10-next-publish.progress.md)). 변환기는 제목의 평어체, 번역투, 인용문 밖 설명의 뜻과 문장 리듬까지 판단하지 못하므로 S6 윤문과 독립 내용 검토를 생략하지 않는다. 역사 실행은 새 변환기로 다시 만들지 않는다.
- **L26 — 법령은 기본 시행일만 보지 않는다**. `MST`와 `efYd`로 기준일 현행본을 고르고 실제 응답 시행일, 부칙, 조항별 유예를 함께 읽는다. 식품표시의 2028년 시행예정 규정, 제31절 군복무 경력의 2027-02-20 시행예정 조문, 제11절 안전성 고시 제8조의 2026-10-31 유예를 현재 의무로 쓰지 않는다. 반대로 국민건강보험법 시행령 MST 289701의 별표 2는 제5호의2만 2027-01-01로 유예되고, 제1호·제3호까지 미래 규정인 것은 아니다. 각 절의 조사 기록에 현행·미래 원문 대조를 남긴다.
- **L27 — 공개 본문 수정은 현재 파일을 재검토한다**. 공개 본문을 고치면 리뷰 해시가 달라진다. `gate --demote`로 임시 🟨 상태로 전환하고, 새 독립 검토와 현재 해시 게이트를 통과한 뒤 `promote`로 ✅를 복원한다. 옛 실행의 `assemble`을 다시 돌리면 공개 후 수정이 덮어써질 수 있다. 미확인 수치·판례·가격은 본문과 TODO에 한계를 밝히고 2차 조사로 남긴다. pass는 모든 TODO가 해소됐다는 뜻이 아니다.
- **L28 — 재현 가능한 검사와 배포 상태를 구분한다**. 도구는 저장소 밖 `/workspace/.cache/howtolivebetter/`에 두고 `source /workspace/.cache/howtolivebetter/activate.sh`로 활성화한다. 브라우저 검사는 file:// 대신 loopback HTTP로 한다. 실행 명령·대상·결과를 진행 기록에 남기고 실제 완료한 검사만 보고한다. 세션 브랜치의 빌드 성공과 Pages·릴리스 배포는 다르다. 사용자 PR 병합 뒤 main 워크플로가 배포하며 저장한 환경 설정도 별도 게시와 다음 세션 검증을 구분한다.

- **L29 — 의학 수치의 대상과 단위도 원문 범위를 보존한다**. 제2절 재검토에서 “붉은 고기 합계”가 “고기 전체”로, “달걀 전체 반 개”가 “노른자 반 개”로 바뀐 문제를 확인했다. 수정 담당자가 Europe PMC 원 초록과 PLOS 원 논문을 직접 열고 중국 원문의 여섯 필드를 대조해 범위와 단위만 최소 수정했다. 숫자·DOI·근거등급은 보존했고 새 독립 검토를 거쳤다. 링크와 숫자가 같아도 대상 범위가 달라지면 의미가 바뀐다([제2절 조사 기록](chapters/02/2-research.md)).
